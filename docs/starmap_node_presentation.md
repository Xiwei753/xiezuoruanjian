# 星图普通节点呈现规范 v1.0

Status: active
Last verified: 2026-10-22
Truth source: product decision / Issue #984
Related: [starmap_semantics.md](starmap_semantics.md) · [starmap_viewport.md](starmap_viewport.md)

## 概述

星图普通节点不是只能放一个名字的标签，而是可以直接承载文字内容的创作卡片。一个节点有两个明确的用户字段：

* **节点名称 `title`**：用于识别节点。
* **节点正文 `content.body`**：节点承载的内容，可以包含多行、手动换行和多个段落。

两者分属不同字段、分别编辑、分别保存。正文不得拼进 `title`、`payload` 或边标签，也不得为正文另建一份旁路数据。

普通节点与子星图 Embed（圆形入口）是两类不同对象：节点是文字卡片，Embed 是进入另一张画布的圆形入口。本规范不改变 [starmap_semantics.md](starmap_semantics.md) 定义的对象关系、连线规则和子图穿越规则。

## 数据契约

普通文字节点沿用 Core 已有的：

```
StarMapNode {
    title: String,
    content: StarMapNodeContent::Inline {
        summary: Option<String>,
        body: Option<String>,
    },
}
```

* UI 中的“节点内容”写入 `content.body`。
* `content.summary` 是已有的可选摘要，不是第二个名称，也不得用来覆盖正文。
* 正文允许包含 `\n`、连续空行和中文输入法提交的多段文字；保存正文不得 `trim()`，不得丢失段落首尾或中间空白。
* 不设置武断的硬字符上限；预览的折叠只发生在显示层，存储始终保留完整正文。

### 内容类型

* `empty`：节点尚无内容。首次保存正文时转为 `inline`。
* `inline`：节点正文使用 `summary` / `body`。
* `chapterRef` / `entityRef` / `externalRef`：引用型内容。用户只修改名称时必须保留原引用类型和引用字段，不得因为编辑标题而改写成 `inline`；正文编辑器不接管引用内容的语义。
* 局部更新使用 Core 的 `StarMapNodePatch.content`（省略即不修改）。不需要新增 Core 表或第二套节点 DTO。

节点名称与正文的更新属于同一个节点对象，跨平台同步继续按该节点的 `updated_at` 和既有收敛规则处理，不建立“正文另存一份”的旁路。

## 卡片呈现

普通节点在画布上呈现为文字卡片，至少包含两个区域：

1. **名称区**：位于上方，字号更大、字重更醒目。名称过长时允许视觉自动折行，标题文本本身仍是 `title` 字段。
2. **正文预览区**：位于下方，字号较小，保留换行。正文较长时在卡片内折叠，并在超出预览行数时显示省略提示。

规则：

* 没有正文时可以只显示名称；有正文时卡片自然变高。
* 卡片宽度和最小高度由平台给出适合本端的默认值；内容高度按文字测量增长，但正文预览有可读的最大展示高度（建议默认 4～6 行，具体像素由平台排版与字号决定）。
* 预览折叠不得修改存储内容，不得用 `substring` 截断后回写 Core。
* 节点 `position` 始终是卡片左上角。文字换行只改变平台派生的显示尺寸，不修改 authored position，也不为正文单独创建节点或连线端点。
* 名称与正文的层级由排版区分；不能把正文当第二个名称，也不能只显示名称而让正文永远不可见。

### 尺寸与交互几何

卡片尺寸是平台显示层派生的结果，不是 Core 的持久化字段。同一平台上必须使用同一份节点度量结果生成：

* 绘制矩形与文字区域；
* 点击/拖动命中测试；
* 连线端点与外轮廓交点；
* 移动安全区与碰撞规避；
* fitView / 缩放到内容的包围盒；
* 子图概览投影中的节点占位。

卡片变高后，不能出现“画出来了但点不到”或“连线落在卡片中间”的几何漂移。低倍率下可以只做视觉细节降级（例如隐藏正文预览），但不改变节点身份、坐标、尺寸派生规则，也不让 Embed 的圆点显示姓名。

## 编辑行为

双击（触屏为双击/双触）普通节点进入编辑。节点右键/长按菜单中的“编辑”使用同一入口。

* 名称单独一栏，保持单行输入。
* 正文是可输入回车的多行区域（Qt 使用 `TextEdit`，鸿蒙/Android 使用原生多行输入控件）。按 Enter 插入换行，不得把 Enter 当成保存动作。
* 编辑期间卡片可以按完整正文展开或使用平台原生编辑浮层；完整正文必须全部可见并可继续输入，不能只让用户编辑预览中被截断的部分。
* 提交方式由平台定义（Qt 可用 Ctrl+Enter 提交、Esc 取消；触屏端使用保存/取消按钮）。中文输入法预编辑期间不得提交。
* 文本控件在编辑期间认领键鼠/触摸输入；退出编辑后恢复画布手势。
* 保存时分别发送 `title` 和 `content`（正文可编辑且确有正文时使用 `inline`）；标题为空或正文为空的校验由平台按本端交互决定，但正文存储不做 `trim()`。

## 与 Embed 的关系

* 普通节点是卡片，Embed 是正圆入口；两者的视觉、命中区域和进入行为保持区分。
* 缩放档位只影响 Embed 圆内预览的细节程度，不改变 Embed 的 world 几何、节点坐标或卡片尺寸。
* 子星图概览里仍可将普通节点画成小圆点且不画名字；进入活动画布后恢复完整卡片。
