# 星图画布模型契约

Status: active
Last verified: 2026-06-13
Truth source: product decision / architecture discussion
Scope: StarMap storage, rendering, linking, AI proposal, and cross-platform behavior

## 1. 总纲

星图不是作品的附属物，也不是后台关系库的筛选视图。

星图是用户创建的、所见即所得的、可缩放的关系画布。

创建就是创建，链接就是链接：

- 创建作品只创建作品。
- 创建星图只创建星图。
- 创建节点只创建节点。
- 创建线只创建线。
- 作品、章节、节点、星图之间的关联，必须通过用户明确动作建立。

任何实现不得把“新建作品”隐式改造成“新建作品并自动创建/绑定星图”。

## 2. 核心定义

### 2.1 StarMap：星图

StarMap 是一张独立画布。它可以有：

- 标题。
- 简介。
- 正文说明。
- 标签。
- 默认入口/默认视口。
- 内部节点。
- 内部子星图。
- 内部线。
- 布局数据。
- 视觉过滤配置。

StarMap 本身可以承载内容，也可以承载画布结构。

StarMap 可以被另一张 StarMap 包含。被包含时，它在父星图中是一个星图对象，而不是节点。它可以随缩放表现为星团、亮点、缩略画布或可进入的空间。

### 2.2 Node：节点

Node 是原子内容卡片。

Node 不能继续包含子节点，也不能被实现成无限套娃容器。

Node 可以有：

- 标题。
- 类型。
- 简介。
- 正文备注。
- 标签。
- 元数据。
- 文本/内容超链接。

如果一个对象需要继续承载内部结构，例如“帝国”里还有派系、城市、人物、事件、关系，那么它应该是一张 StarMap，而不是 Node。

### 2.3 Child StarMap：子星图

子星图是另一张 StarMap 被放进当前 StarMap。

子星图不是 Node。

子星图可以作为线的端点，也可以作为 EndpointPath 的中间层级。

### 2.4 Edge：线

Edge 是用户在当前 StarMap 中创建的关系线。

线就是线。它不是超链接，不是包含关系，也不是视觉辅助线。

Edge 可以有：

- label：线上显示的文字。
- kind：用户注册的线类型，可为空。
- note：悬浮说明或详情。
- style：箭头、双向、虚线、实线等可选视觉属性。
- fromEndpoint：起点。
- toEndpoint：终点。

线的语义不强制写死。系统可以提供预设类型，例如：

- 未分类。
- 关系。
- 因果。
- 从属。
- 时间。
- 引用。
- 冲突。
- 同盟。
- 伏笔。
- 回收。

但必须允许用户自己注册类型。用户能够理解自己画的是什么，是第一原则。

删除线就是删除这条关系。

隐藏线是独立的视觉过滤动作，不是删除。

### 2.5 Hyperlink：超链接

Hyperlink 不是线。

Hyperlink 是文本或内容上的跳转能力。它可以出现在：

- 正文字符。
- 节点正文。
- 星图介绍。
- 线的说明文字。

桌面端可以使用 Ctrl+点击、悬浮按钮、右键菜单。触摸端可以使用长按、弹出菜单、点击小图标等方式。

Hyperlink 可以跳转到：

- 作品。
- 卷。
- 章节。
- 正文锚点。
- 节点。
- 星图。
- 星图内部路径。

Hyperlink 不应该在星图画布上默认画成关系线。

## 3. 包含不是线

星图包含节点、星图包含子星图，这属于空间结构，不属于 Edge。

例如，“工具星图”里面有 GPT、Claude、Mimo，这不是：

```text
工具星图 —— GPT
工具星图 —— Claude
工具星图 —— Mimo
```

而是：

```text
工具星图里面放着 GPT
工具星图里面放着 Claude
工具星图里面放着 Mimo
```

包含关系不需要画线。

实现上必须区分：

- containment：星图里放了什么。
- edge：用户明确画出来的关系线。
- hyperlink：文本或内容里的跳转。

这三者不能混用。

## 4. EndpointPath：路径端点

线的端点不能只支持单个 nodeId。

线的端点必须支持 EndpointPath。

EndpointPath 是一条可以层层进入子星图的地址链。路径里的每一级都是有效的。

例如：

```text
我 ——（工具）—— 工具星图
```

目标路径是：

```text
工具星图
```

再例如：

```text
我 ——（最常用工具）—— 工具星图 / GPT
```

目标不是“只指向 GPT”，也不是“只指向工具星图”，而是指向完整路径：

```text
工具星图 -> GPT
```

更深层级也必须支持：

```text
我 ——（最常用模型）—— 工具星图 / AI工具星图 / 大模型星图 / GPT
```

目标路径是：

```text
工具星图 -> AI工具星图 -> 大模型星图 -> GPT
```

### 4.1 EndpointPath 示例

```json
{
  "type": "endpointPath",
  "path": [
    { "type": "starmap", "id": "tools" },
    { "type": "starmap", "id": "ai-tools" },
    { "type": "starmap", "id": "llm-map" },
    { "type": "node", "id": "gpt" }
  ]
}
```

### 4.2 路径端点的渲染规则

数据目标永远是完整路径。

视觉目标按缩放解析到当前可见层级。

远景时，线可以视觉上落到外层星图亮点。

中景时，线可以落到子星图内部区域。

近景时，线可以落到最终节点或最终子星图对象。

这不是隐藏，也不是改数据。它只是同一个 EndpointPath 在不同缩放层级下的解析精度不同。

## 5. 缩放、线粗细与星系感

线的粗细主要来自缩放，而不是来自语义重要度。

父星图里的线看起来较粗。

子星图缩小后，里面的线自然变细。

继续缩小时，线可以变成光丝、淡线或微弱结构，节点和子星图可以变成亮点，于是自然形成星系感。

实现上可以使用类似规则：

```text
screenLineWidth = worldLineWidth * currentScale
```

线的语义重要度不应该默认映射为粗细。若未来需要线权重，也必须作为用户显式视觉属性，不得污染“缩放导致粗细变化”的主规则。

## 6. 简化不是隐藏

远景必须允许渲染简化，否则复杂星图会变成毛球。

简化是缩放渲染策略，不改变数据。

可接受的简化包括：

- 线标签消失，只剩线。
- 箭头细节消失。
- 小节点变成亮点。
- 子星图变成星团亮点。
- 内部细线变成光丝。
- 多条过密线视觉弱化。
- 放大后恢复细节。

隐藏是用户主动执行的视觉过滤动作。隐藏不改变数据，但必须可见、可恢复、可管理。

## 7. 过滤是视觉效果

不需要单独创建“人物关系图”这种数据类型。

只要节点有类型、线有类型、对象有标签，就能通过过滤实现：

- 只显示人物。
- 只显示人物之间的线。
- 只显示时间线。
- 只显示因果线。
- 隐藏某类线。
- 隐藏某类节点。
- 只显示某个标签。

过滤是视觉效果，不改变星图数据。

类型可以有系统预设，但必须允许用户自己注册。

## 8. AI 建议与正式星图隔离

AI 不允许直接污染正式星图。

AI 可以生成临时星图或临时 patch。用户确认后，才进入正式星图。

可接受的 AI 产物包括：

- AI 建议图。
- AI 新增节点建议。
- AI 新增线建议。
- AI 建议超链接。
- AI 修改说明建议。

底层可以使用候选变更树或 patch 表示：

```text
proposals/
└── ai/<proposal_id>/
    ├── starmap_preview/
    ├── patch.json
    └── explanation.md
```

产品上不应要求用户理解 Git 分支。用户只需要看到：

- 全部接受。
- 局部接受。
- 另存为新星图。
- 丢弃。

## 9. 存储路线

不使用 SQL 作为星图真相库。

星图真相仍然是 Git 友好的文件仓库。

但不能长期用一个巨大 `starmap.json` 保存所有内容。

星图应该保存为图谱包：

```text
starmaps/
└── <starmap_id>/
    ├── graph.json
    ├── nodes/
    ├── child_starmaps/
    ├── edges/
    ├── hyperlinks/
    ├── layouts/
    └── metadata/
```

### 9.1 文件职责

- `graph.json`：星图元信息、schemaVersion、标题、简介、默认入口、对象顺序等。
- `nodes/`：当前星图内的原子节点。
- `child_starmaps/`：当前星图包含的子星图放置对象。
- `edges/`：当前星图内用户创建的线。
- `hyperlinks/`：文本或内容跳转链接。
- `layouts/`：布局、坐标、缩放、折叠、视口等显示数据。
- `metadata/`：索引辅助信息、迁移标记、兼容信息等。

### 9.2 Git 友好要求

- 改一个节点，只动一个节点文件。
- 改一条线，只动一条线文件。
- 拖动布局，只动布局文件。
- 修改超链接，只动超链接文件。
- JSON 写入必须稳定排序。
- JSON 应使用 pretty format，方便人工检查和 Git diff。

### 9.3 SQLite 的边界

SQLite 以后可以作为本地索引和缓存，例如：

- 快速搜索。
- 快速查 EndpointPath。
- 快速查某节点相关线。
- 快速查某星图包含对象。
- 快速重建视口快照。

但 SQLite 必须满足：

- 可删除。
- 可重建。
- 不参与同步真相。
- 不保存唯一用户数据。
- 不替代 Git 文件仓库。

## 10. 删除、隐藏、迁移

删除线 = 删除关系。

隐藏线 = 当前视觉过滤隐藏，不删除关系。

删除节点时，必须处理与该节点相关的线、EndpointPath、超链接。可以提供确认和修复建议，但不能静默制造断链。

删除星图时，必须检查：

- 是否被其他星图包含。
- 是否被 EndpointPath 引用。
- 是否被 Hyperlink 引用。
- 是否有 AI proposal 指向。

旧单文件星图格式迁移到图谱包时，必须保留兼容读取能力，并提供一次性迁移路径。

## 11. 与当前代码的收口方向

当前 Core 已经有 `StarMapGraph`、`StarMapNode`、`StarMapEdge`、`StarMapLink`、`StarMapEmbed` 等模型。

后续实现应逐步收口到：

- StarMapGraph 内存模型可以继续存在，但落盘不能长期依赖单个大 JSON。
- 旧 `from` / `to` 字符串字段只能作为兼容字段，不应作为新功能主路径。
- 新功能应以 EndpointPath 作为 Edge 端点。
- child StarMap 必须和 Node 区分，不能把子星图伪装成节点。
- containment、edge、hyperlink 必须分开建模。

## 12. 禁止事项

禁止把星图做成作品的强附属物。

禁止创建作品时自动创建或绑定星图。

禁止把 Node 做成无限嵌套容器。

禁止把子星图伪装成 Node。

禁止把包含关系画成 Edge。

禁止把 Hyperlink 画成 Edge。

禁止用视觉辅助线承载含糊关系。含糊关系也应该是未分类 Edge。

禁止用隐藏冒充删除。

禁止 AI 直接写入正式星图。

禁止使用 SQLite 作为星图真相库。

## 13. 最终定义

星图是独立画布。

节点是原子内容卡片。

子星图是另一张星图被放进当前星图。

线是当前星图里的关系对象。

线的端点是路径，可以一路进入子星图内部。

超链接不是线。

包含不是线。

过滤是视觉效果。

简化是缩放渲染策略。

AI 只能生成临时建议，用户确认后才进入正式图。
