# 素笺产品设计契约

> 本文档整理自 2026-06-08 的产品定位与交互边界讨论。它不替代技术路线文档，但后续涉及产品体验、AI、保存、星图、视觉主题、提醒机制时，应优先参考本契约，避免 AI 或人工改动把产品方向带偏。

## 1. 产品定位

素笺的第一印象不是三选一，而是分层共存：

- 底色是安静可靠的私人书房。
- 能力上是专业长篇创作工作台。
- 体验上像一个不抢戏的创作伙伴。

素笺不是 AI 小说生成器，也不是批量代写流水线。它服务真正还在写作现场的人：自己写、自己改、自己搭世界观、自己管理作品。AI 可以辅助整理、分析、查漏、维护设定和星图，但不能成为正文主权。

纯靠 AI 代写的人不是目标用户。这样的人一个终端 CLI 或网页表单就够了，不需要素笺费心做写作手感、光标动画、莫奈取色、星图和保存安全。

## 2. 作者自由

素笺不做写作流程警察。

用户想正规写小说、写设定集、写纯文本、写代码、写大纲、只写不整理星图、不开 AI、关掉同步，都可以。软件只负责安全、稳定、可恢复、好写，不负责管教作者怎么创作。

高风险问题必须明确提醒，但不强制替用户做决定。用户愿意把红色警报当氛围灯，不归软件管。软件的责任是把风险讲清楚、摆出来，而不是抢走作者手里的笔。

## 3. 不丢稿红线

素笺的产品底线是：不丢稿，尤其不能丢一整章。

“自动保存成功”不能由 UI 自己判断，不能由保存队列收到任务就判断，不能由编辑器 buffer 有内容就判断，也不能由普通文件写入成功就随便判断。

保存状态必须分层：

- 已输入：内容只在编辑器 buffer 中，不能算保存。
- 已落盘：正文文件已经安全写入工作区，但仍不能对用户叫最终保存。
- 已保存：内容已经进入本地 Git 历史。
- 已同步：对应保存版本已经推送到远端。

只有 Core 完成正文原子写入，并且内容已经进入本地 Git commit，前端才允许显示“已保存”。Push 成功之后，才允许显示“已同步”。

绝对禁止：

- UI 假成功。
- QML / Android UI / ViewModel 自己猜保存成功。
- 保存队列收到任务就显示成功。
- 文件写一半显示成功。
- 空内容、旧内容、半截内容被当作正常正文覆盖进历史。
- 同步失败影响本地“已保存”的承诺。
- 远端旧版本静默覆盖本地新版本。
- 冲突时自动吞掉任意一边。

原则是：宁可多留十个废版本，也不能静默覆盖一个有效版本。

## 4. Git 历史与版本星图

素笺应主动使用 Git 历史作为防丢稿底座，但不向普通用户暴露 Git 术语。

每次用户感知到“已保存”的稳定版本，都必须对应一个本地 Git commit，并能返回 commit id 或等价版本标识。UI 可以展示时间、章节、字数变化、保存设备、本地/远端状态、冲突状态，但不应在普通界面展示 hash、HEAD、branch、tree、blob 等 Git 术语。

版本历史优先做成“版本星图”，而不是普通列表。

版本星图是从 Git commit graph 派生出来的只读系统视图，不是用户可编辑的创作星图。它可以共用星图渲染器和缩放交互，但不能混入角色、事件、设定那套 StarMapGraph 业务模型。

版本星图规则：

- 中心可以是当前章节或当前作品。
- 保存节点按时间和版本关系展开。
- 本地线、远端线、同步合并、冲突分叉应可视化。
- 冲突节点用红色高风险语义显示。
- 历史很多时，UI 折叠显示：今天细、昨天按小时、更久按天/周/月聚合，放大后再展开。
- 历史是安全资产，不是垃圾。默认不删除用户可见历史。

恢复旧稿时，不能做 Git reset、rebase、amend，也不能破坏后续历史。

正确做法：用户选择旧版本 → Core 从该 commit 读取章节内容 → 写回当前章节 → 生成新的保存 commit。这样即使恢复错了，也能再次恢复回来。

自动保存 commit 粒度：

- 平时约 30 秒节流保存。
- Ctrl+S 立即保存。
- 切章节、切页面、退后台、关闭应用、同步前强制保存。
- 内容没变不 commit。
- 用户连续输入时可合并小变化，避免每个标点一个版本。

Git 树需要主动管理，但不要以删除历史为代价。纯文本章节的 Git 历史通常体积可接受。主要通过保存节流、版本星图折叠、Git gc/maintenance、同步白名单、附件隔离来控制体积。维护任务必须后台低优先级执行，不得打断写作，也不得与保存/同步并发抢仓库锁。

## 5. 高风险提醒

涉及不丢稿、安全保存、Git 入库失败、远端覆盖风险、同步冲突、工作区损坏、章节读写异常等问题时，必须全局强提醒。

高风险提醒应表现为红色全局风险提示，用户无论在写作页、星图页、设置页、工作台还是同步页，都应该能看到。

但强提醒不等于强制拦截。默认不打断用户写作，不强制关闭编辑器，不强制跳转页面。只有危险操作本身必须二次确认时，才做操作级确认。

软件的责任是明确、醒目、持续地告诉用户“现在有风险”，选择权仍归作者。

## 6. 启动、现场恢复与统计

素笺打开后应回到用户离开时的现场。

不是默认进正文，也不是默认进工作台，而是：从哪里离开，就从哪里回来。

例如：

- 上次在某章写作，下次回到该章节和大致光标位置。
- 上次在作品首页，下次回作品首页。
- 上次在星图中整理关系，下次回该星图视角。
- 上次在设置页、同步页、工作区页，也尽量恢复。
- 恢复失败时，退回安全页面，如作品首页或工作台。

统计归统计页。不要开屏仪式感，不要打开应用就展示今日字数、连续天数、总进度，不要把统计塞进主流程。

目标系统可以有，但默认没有。用户自己想设每日目标或作品目标，可以设置；不想设，软件保持安静。

不做成就系统，不做徽章、奖杯、等级、经验值、连续签到、断签焦虑。状态反馈可以有，如“本章已保存”“已恢复旧稿”“已同步”，但这些是状态，不是游戏化奖励。

## 7. 联网、账号与社区

素笺不是默认离线软件。联网是默认能力。

软件可以默认检查网络状态、检查更新、检测同步可用性、探测代理、刷新远端状态、准备 AI 服务状态。不要让用户为每个模块单独理解“是否允许联网”。

但默认联网不等于默认上传正文给 AI，也不等于默认云端托管。正文、设定、星图什么时候发给远端，必须由具体功能语义决定，不能后台偷偷发送整个工作区。

素笺不要自己的账户体系：

- 没有素笺账号。
- 没有素笺云。
- 没有会员中心。
- 没有头像昵称。
- 没有用户等级。
- 没有中心化作品托管。

用户需要同步，使用自己的 GitHub / Git 仓库。用户需要 AI，配置自己的 AI 服务、API Key 或 CLI。喜欢分享可以去 GitHub Discussions、Issues、外部论坛或社交平台。

素笺不做内置社区、广场、发布、投稿、推荐流。它是创作工具，不是内容平台。

## 8. AI 路线

开发期 AI 优先做 CLI 旁路，API Provider 后置。

原因是现阶段可利用已有的 Plus、Gemini Pro、NVIDIA API、国产模型等额度和工具链，先验证 AI 交互、上下文读取、工具调用、动作按钮、错误提示和权限边界。后续再补 OpenAI-compatible、DeepSeek、Kimi、GLM、Qwen、NVIDIA 等 API Provider。

CLI 先做，不等于把终端暴露给用户。素笺应提供自己的 AI 面板，背后通过 AiRunner 调用不同 CLI 或 API 后端。

内部应统一成素笺自己的 AI 事件模型，例如：

- TextDelta：模型输出文本。
- ToolCallRequested：模型请求工具。
- ToolCallResult：工具结果。
- ReasoningSummary：可选思考摘要。
- ActionProposal：建议用户点击的动作按钮。
- Error：失败、超时、鉴权错误、格式错误。
- Done：本轮结束。

不要让 UI 直接依赖 Codex CLI、Gemini CLI、OpenAI、Anthropic、国产模型或 NVIDIA 的私有格式。每个供应商/CLI 的奇怪格式只能脏在 adapter 内部。

MCP 解决工具接入标准化，不解决模型思考链。素笺不追求裸思考链，追求工具行为透明。

AI 应展示：它读了哪些上下文、调用了哪些工具、准备执行哪些动作、是否会改正文/星图/设置。用户点不点，用户说了算。

AI 不能直接改正文，不能直接写工作区，不能绕过 Core。所有 AI 建议最终都应转成素笺自己的 AiAction，由用户确认后通过 Core capability 执行。

## 9. 莫奈动态取色与视觉主题

莫奈/动态取色是普通 UI 的氛围层，不是 Core 业务数据。

Android 端普通页面可以优先使用系统 Material 3 Dynamic Color。Linux/桌面端优先跟随 Qt/KDE/SystemPalette，并通过 DesignTokens 映射成统一应用色槽。

动态取色默认按设备本地跟随系统，不做“手机壁纸色同步到电脑”的奇怪功能。设备壁纸色属于端上环境偏好，不应默认写入 settings.sync.json 作为跨端事实。Core 可以保存主题模式、字号、编辑器视觉偏好等设置，但默认不把某台设备的动态壁纸色同步给其他设备。

正文区视觉应安静、低噪音、长时间可读。莫奈色可以用于外壳、按钮、选中状态、滑块和轻量背景层级，但正文文本区必须优先保证对比度、可读性和稳定性，不能因为壁纸颜色导致正文发灰、发脏、刺眼或不清楚。

## 10. 星图定位

星图不是普通思维导图，也不是 AI 控制台。它是正文之外的结构空间，用来承载故事元素、关系、引用、嵌入和跳转。

星图服务复杂长篇创作中的人物、事件、地点、组织、伏笔、冲突、章节、设定之间的关系管理。用户不用也没关系，软件不强迫整理星图。

星图语义原则：

- StarMap 是独立文档对象，不是强依赖父子拥有权的嵌套树。
- 一个星图可以 Embed 另一个独立星图的实例。
- Link 只是跳转或引用，不拥有目标。
- 删除 StarMap 时必须做引用安全检查，不能静默级联删除被其他星图引用的对象。
- DeepTarget / Path 可以指向跨层级目标。
- Graph 是业务真相，Layout 是位置和缩放，Snapshot 是给前端渲染的只读视图。

## 11. 星图导航

星图默认打开位置由入口来源决定，不是固定默认页。

规则：

- 从独立入口打开星图：进入星图主页面，展示星图列表、最近打开、作品绑定星图、宇宙图、独立星图。
- 从某个星图卡片或列表打开：直接进入该星图，并恢复上次 viewport、选中节点、缩放状态。
- 从正文超链接进入：定位到链接指向的目标，如节点、关系、嵌入星图、锚点，并高亮来源目标。
- 从作品写作页进入：优先进入该作品绑定的主星图；如果当前章节有章节级星图、章节锚点或相关节点，应尽量详细到章节相关视图；没有章节绑定时退回作品主星图；没有作品星图时提示创建，但不强迫。
- 从角色、事件、设定、章节等对象进入：直接定位到包含该对象的星图位置；如果多个星图引用它，优先最近使用/主星图，并提供其他引用位置入口。

优先级是：入口上下文 > 最近现场 > 作品绑定 > 安全默认页。

## 12. 星图视觉与缩放

星图区使用独立局部主题。默认深色高对比、低装饰、低噪音，不跟随正文区的温润莫奈氛围。

但不要硬编码绝对黑白。应通过 StarMapPalette / StarMapTheme / 局部 token 管理颜色，便于后续支持高对比、浅色、打印、色盲友好或用户自定义。

星图颜色只服务语义：选中、搜索匹配、冲突、断链、警告、引用路径。不要为了酷搞花哨霓虹，也不要让莫奈色污染星图结构判断。

星图核心体验是缩放：

- 远看是星系：节点像星点或标题，关系线保留主干。
- 中距离是结构图：看见角色、事件、地点、冲突关系。
- 近看是卡片：标题、摘要、正文锚点、引用、备注、AI 发现的问题。
- 进入嵌入星图时，像进入子星系，而不是打开普通子页面。

Android 星图短期可用 Canvas 自绘验证，长期预留 Surface/OpenGL 后端。Linux 星图短期可用 QML/Qt Quick + 局部 token，后续性能不足时再升级 SceneGraph/QQuickItem 渲染。UI 不保存星图业务真相，不私自判断引用安全，不静默删除目标。

## 13. 星图边与关系标签

星图关系可能不对等，因此不能强行用一条双向边表达所有关系。

对等关系可以用无方向边或双向边，例如朋友、同盟、相互冲突。不对等关系应使用单向边，例如从属、控制、保护、欺骗、因果、伏笔指向。如果双方关系不同，应使用两条单向边。

同一对节点之间多条边时，视觉上应画成一组平行弧线或不同曲率的曲线，避免完全重叠。

边标签规则：

- 边标签是一个整体文本块，不是每个字单独摆放。
- 默认保持屏幕水平可读，不随线旋转，不竖排，不倒置。
- 线和箭头负责表达方向，文字不跟着线翻转。
- 节点拖动时，边线跟着节点变化，箭头跟着线方向变化，标签作为整体跟随边的中点或控制点移动，文字方向不变。
- 拖动中优先稳定，不做完整标签重排；松手后再做局部避让。
- 缩小视图时可以隐藏边文字，只保留颜色、箭头和线型；放大后再显示标签。
- 标签应有背景胶囊或轻量底板，避免裸文字压在线上。

如果一条边需要多个说明，可以支持多个整体标签，例如 main / source / target：主标签放中间，source label 靠起点，target label 靠终点。

默认不要使用沿线旋转文字。以后可作为高级选项，但必须防倒置，并加入滞后阈值避免 90 度附近来回翻转抖动。

## 14. 当前短期实现重点

当前路线不需要换技术栈，重点是继续收口：

- 将“已保存”严格绑定到本地 Git commit。
- 保存结果返回 commit id 或版本标识。
- 建立版本星图派生视图，恢复旧稿生成新 commit。
- QML 不再直接解析业务 JSON，解析和状态映射收回后端适配层。
- 编辑器巨石文件后续拆成输入适配、布局、渲染缓存、光标动画、编辑 buffer、scene graph 节点等模块。
- 星图/导图写入口继续统一到 Core capability。
- 视觉 token 可替换，禁止为了视觉效果把颜色硬编码进渲染层。
- AI 先做 CLI 旁路和统一事件模型，再补 API Provider。
